# Neovim

Native Lua configuration using `vim.pack`, currently targeting Neovim 0.12.6.
Experimental ui2 owns command-line/messages, Snacks handles notifications, and
LSP hover/signature use Neovim's native handlers. Futaba/Oracle follow system
appearance in normal UI sessions. Mouse input and the statusline are disabled.

`init.lua` explicitly loads options, package declarations in `lua/config/pack.lua`,
feature setup modules under `lua/plugins/`, autocmds and keymaps. Optional ignored
`lua/plugins/local.lua` and `lua/choco14t/private.lua` files can override local
settings; absent files use public defaults, while errors in present files remain
visible.

## Repository sessions

Home Manager deploys configuration files through the Nix store. To work with the
repository source, run this from the repository root:

```sh
DOTFILES_ROOT="$PWD" nvim-dotfiles
```

`nvim-dotfiles` defaults to `~/.dotfiles` when `DOTFILES_ROOT` is unset. The user
runs `:restart` in this session to reload repository edits. Restarting a deployed
session continues to use its Nix-store configuration.

## Plugin maintenance

In a repository session, press `<leader>pu` (Space, p, u) or run:

```vim
:lua vim.pack.update()
```

Review the confirmation buffer; `:write` applies the proposed changes and `:quit`
discards them. The user can then restart the session to load updated code.

`nvim-pack-lock.json` is generated by `vim.pack` in the active configuration
directory. Keep it writable and unmanaged, rather than linking it into the Nix
store. It is ignored by Git, untracked, and excluded from the Git-based flake
source. Plugin updates need no lockfile commits, handwritten commit pins, or
routine snapshots. Fresh installations may resolve different revisions within
the declared branch/release constraints.

Git rollback restores source configuration, not exact installed plugin revisions.
If you already have a local lockfile snapshot stored outside this repository,
copy it over the active `nvim-pack-lock.json`. Restart the repository session
yourself so `vim.pack` rereads it, then review restoration with:

```vim
:lua vim.pack.update(nil, { target = "lockfile" })
```

Use `:write` to apply or `:quit` to discard. This optional recovery uses an
existing snapshot; no backup file or snapshot commit is required by normal use.

## Source verification

With required plugin checkouts already available, run from the repository root:

```sh
XDG_CONFIG_HOME="$PWD/files/config" nvim --headless +qa
```

Inspect output as well as exit status, and inspect changed mappings with
`:verbose nmap`, `:verbose xmap`, `:verbose imap`, or the appropriate mode.
Headless sessions skip Mason tool, Treesitter parser, and Blink binary
provisioning; `vim.pack.add` can still fetch missing plugin checkouts. These
checks do not establish UI rendering, completion, formatting, parser execution
or normal provisioning behavior. OS-theme polling and Incline setup run only
with an attached UI.
